# Green Zone MO Guide

A phone-first reference for medical officers (MOs) and house officers (HOs) working in the Green Zone (MTS levels 4 and 5) of the Emergency & Trauma Department, Hospital Kuala Lumpur. The owner is Krishna, an MO in that department. MOs open it mid-shift on a phone, with little time per question, so judge every change by on-shift use first: fast lookup, one tap to an answer, a phone layout and little mobile data. The journey, tour, quiz and poster are extras for new staff.

## Commands

Run these in `src/`. They need Node.js 18 or later. Set up the test once with `npm install` and then `npx playwright install chromium`.

```
npm run check    # content check: expect "71 entries; rules: 24" and "no errors"
npm run build    # writes ../green-zone-pathways.html, ../app/index.html, ../app/manifest.webmanifest and ../app/sw.js
npm run icons    # redraws ../app/icons/ from the brand mark (only when the mark changes)
npm test         # Playwright walk-through: expect "errors: none" and "all checks passed"
npm run serve    # preview the offline copy at http://localhost:8765
npm run all      # check, build and test in one go
npm run webkit   # the main views in Safari's engine at iPhone size (WebKit in C:\Users\user\tools\ms-playwright): expect "no problems"
```

After any change in `src/parts/`: run check, build and test, then look at the screenshots in `src/shots/` for the views you touched (`d-` desktop, `p-` phone, `pd-` phone dark, `t-` tablet). The test checks for console errors, sideways scroll on every view, search, the step runner, deep links, tabs, tools, quiz, journey and settings, and that no film from `media/` loads before a tap (from each page's own requests); the tour film then plays through a chapter, a line of the transcript, Resume, the language switch and Day and Night. It also checks the version 8 features: the zone map, the whole-pathway map, "Can still end in", the route meter, the gauges and the intro; and the calculators: every route, the hub and its find, the PEMCalc links, the scores and verdicts, the shared weight, that every number is still in its source text, and that using them stores nothing. It uses the version 8 ids, so update it when you change the markup. The pages it opens register the service worker as the web app does. Its web app checks run on a second server, `PORT + 1`: the manifest (as Chrome reads it, its colours, start_url and scope on Pages, the icons at their sizes, the shortcuts), the worker saving exactly the page, manifest and small stills and fetching no film or sound ahead, the Settings row, a sound kept once played (from the player's own download) and a byte range not kept, a reload with the network off (home, a pathway, a calculator, the tile pictures, the kept sound with byte ranges), an update (a newer `sw.js` takes over, copies the unchanged files without downloading them, deletes the old cache but not another site's, and the open page offers Reload), no worker on 127.0.0.1, and no trace of any of it in the artifact. Install the guide is checked there too: the live state (Ready offline with its size, offline, installed), 13 user agents told apart, each device and browser's steps, a simulated `beforeinstallprompt` (Install in the page and in Settings, the prompt opened once), the QR code read back with `qr.js` (which first reads the poster's code), Copy link, the Shift tools tile, search, and the artifact's copy (served as `/artifact.html`: only the note, the link and the code); then at 360 px by day and night and 390 px by night on an Android phone.

## How the page is built

One self-contained page with no framework and no external scripts. `build.js` joins `parts/head.html` with thirty-four scripts, in this order. Since 23 Nov 2026 the page holds them as two `<script>` elements, so the guide starts before the whole page has arrived: the first holds the department's data, the lines marked `// @light` (or in a `/* @light ... */` to `/* @end light */` block) from the eleven files of the second, and `engine.js`; the second holds the rest of `data4`, `5`, `6`, `7`, `9`, `13` to `17`, `24` and all of `34` and `35` (`HEAVY` in `build.js`) and ends with `gzMore()`. A line in one of those files that changes an entry of another file must carry the `// @light` mark (build.js runs the first part's data alone and stops if it fails); a line in a first-part file that changes an entry of the second waits for it in `MORE_AFTER` (data20.js does this for the dengue CPG's link to the observation ward memo). `build.js` also builds the entries both ways, one script and two parts, and stops if any entry comes out differently. ### Content model

Each entry is `P['<id>'] = {...}`. The id is its address (`#renal-colic`).

| Field | Meaning |
|---|---|
| `title` | Name shown everywhere. |
| `page` | Ebook pages, for example `'53–54'`. Only for ebook pathways. |
| `src` | Source and date of a rule entry, for example `'EM Watch, Aug 2023'`. |
| `grp`, `sub` | `grp:'rules'` marks a rule or protocol; `sub` is `'flow'` or `'protocol'`. Ebook pathways have neither. |
| `isnew`, `upd` | Show the New or Updated badge. |
| `lead` | One line under the title. |
| `start`, `nodes` | The first node's key, and the nodes (below). |
| `advice` | Discharge advice lines: a tab, with Copy advice. |
| `concerns` | Practical concerns: a tab. |
| `dept` | Department notes, `[{h, src, items, table?}]`: a tab, each note with its source. |
| `grp:'cpg'` | A national guideline (the seven above and the nine of the third round, in `data7.js`): listed as a Guideline, not counted in the Ebook filter, with its own outcome labels. The library's Guidelines filter (`#guidelines`) shows them, then the CPG shelf (`CPG_SHELF`). One listed in `CPG_SHELF` with its `id` links to its full PDF (Google Drive and the Academy) from its References tab. |
| `ack`, `own` | A guideline's copyright line in the footer of its reference tabs: `ack` names its holder when it is not MaHTAS (ACS, the avulsed tooth CPG); `own:true` marks a CPG summarised in the guide's own words, and its footer says nothing is quoted. |
| `notes` | A guideline's reference tabs, `[{l, notes:[{h, src, items?, table?}]}]`: one tab per `l`. The calculators read Table 5 and the quota table from here (`dTable`). |
| `leaflet` | A two-language leaflet, `{src, en:{lang, title, groups:[{h, p?, warn?, items}]}, ms:{...}}`: the Home care advice tab, with an English and Bahasa Melayu switch (in memory only) and Copy. |
| `tables` | Reference tables, `[{title, head, rows}]`: one tab each. |
| `refs` | References: a tab. |
| `doc` | A rule entry's source document, `{href, t}`: a link to its PDF (Google Drive) in About and in References. The rabies protocol uses it. |
| `notesFoot` | A rule entry's footer for `notes` tabs, in place of the CPG acknowledgement. A note may carry `lang` (`'ms'`), which Read aloud uses to choose its voice. |
| `fig` | On a node or a note: an infographic from `FIGS` in `engine.js` (rabies: `woundcat`, `sched`, `rig`; Code Blue: `cbcall`, `cbmap`, `cbscacc`, `cbclock`, `cbchain`, `cbteam`, `cbcodes`, `cbsheet`; interpreters: `interp`), drawn from the source. |
| `figOnly` | On an outcome: show the figure in place of the list of items; Copy outcome still copies the items (the colour codes). |
| `hero`, `heroj` | A Flow Studio banner (a tile key) behind the entry's title; `heroj` gives it its own jewel instead of the group's (Code Blue is garnet). |
| `kinds` | An entry's own outcome labels, for example `{neutral:'What the guideline says'}` for a guideline that is not a CPG. |
| `kw` | Search words that are not in the text, for the words people type (translator, cardiac arrest). |
| `docs` | Source documents as pills in References, `[[href, label], ...]`: a Drive PDF to open (`/view`) or download (`uc?export=download`). |
| `see` | See-also links, `[['#emacc', 'EMACC follow-up'], ...]`. |

A node is one of three kinds:

- **Question:** `q` and `opts: [[label, nextKey], ...]`, with optional `hint` and `info` (a list shown under the question). Add `check: 'all'`, `'any'` or `'score'` and `items` for a checklist, and the runner highlights an option from what is ticked. For `'all'` and `'any'`, put the "met" or "present" option first and the other second. A score checklist has `items: [[label, points], ...]` and `suggest: s => optionIndex`.
- **Step:** `step` (what to do), `items`, `next`. `kind: 'observe'` labels it Observation.
- **Outcome:** `end` (`'admit'`, `'discharge'`, `'observe'`, `'refer'` or `'neutral'`), `title`, `items`, optional `links` and `gap` (a source line, or what the source does not cover).

To add a **rule entry**, give it `grp:'rules'` and `sub`, and it joins the Flow or Protocols group by itself. To add an **ebook pathway**, also add its id to a group in `CATS` in `engine.js`, or it shows under Other. To add a **step to an existing entry**, do what `data3.js` does: add the node and a menu option pointing to it. Add new search words, quiz questions, numbers or tips in the constants at the top of `engine.js`. Run `npm run check` after every content change.

## Rules of the artifact host

The page is published as a claude.ai artifact, which runs in a locked-down frame. Keep to these, or the page breaks for viewers:

- The published file has no doctype, `html`, `head` or `body` tags; the host adds them. It starts with `<title>Green Zone MO Guide</title>` and `<meta name="claude:viewport-fit-sides" content="cover">`. Keep that title.
- Side gutters use `max(16px, env(safe-area-inset-left, 0px))` and the right-hand equivalent. Nothing may scroll sideways at 390 px.
- Colours are tokens on `:root`, redefined in the two dark blocks (`prefers-color-scheme: dark` guarded by `:root:not([data-theme="light"])`, and `:root[data-theme="dark"]`). No colour may be defined only inside a dark block.
- Fonts only from Google Fonts. Scripts only inline, or from cdnjs, jsDelivr, unpkg or code.jquery.com pinned to an exact version. Media only as files published beside the page.
- Hash routes in plain ASCII letters, digits and hyphens. Never use `settings`, `sidebar`, `customize`, `upgrade`, `downloads` or `comment-*` as a route. No element id may equal a route name.
- Wrap every `localStorage` read and write in try/catch, and make the page work without it.
- No print button, downloads, iframes, `alert`, `confirm` or `prompt`. Sound and narration start only from a tap. Respect reduced motion.
- A film or sound downloads only after a tap too. Never call `load()` on a `preload="none"` player before one: Chrome treats `load()` as overriding preload none and downloads the media (measured on 10 Nov 2026: the tour film's first 26 seconds, about 1 MB, on a first visit). Setting `src` alone downloads nothing. So the tour's film goes in only when the tour opens (`tourOpen` in `engine.js`), and the test fails if any `media/*.mp4` loads before a tap.
- `tel:` links may do nothing in the viewer, so phone numbers stay as selectable text with a Copy button.
- No service worker, web app manifest, touch icon or theme-color meta: those are for the GitHub Pages copy only (`pwa.js`, `sw.js`, `build.js`), and `build.js` stops if the artifact page mentions them.
